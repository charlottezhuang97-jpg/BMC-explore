# HeyPCB · AI PCB 设计工作台

> **为用户完成什么事：**让用户用自然语言提出电路板目标，由 AI 查找器件、生成并迭代原理图与 PCB，再通过规则检查和导出进入制造流程。

- **产品：** HeyPCB（AI PCB Designer）
- **案例任务：**用 FR-4 制作手指心率贴片
- **案例状态：**截图记录到阶段性设计；AI 报告仍有 19 个 DRC 错误和 32 条未布线，不能视为完成或可制造。
- **截图：**21 张，按交互发生顺序编号；含起始方案选择、构建过程，以及后续加载、暂停与继续界面。

## 左侧对话中的任务类型

这 21 张图是**一个持续构建设计的会话**，不是 19 个独立需求。可从中辨认出两层任务：

### 用户面向的任务

1. **自然语言描述目标**：做一个可绕手指佩戴的心率贴片，并指定 FR-4。
2. **澄清关键约束并选方案**：FR-4 是刚性材料，AI 提议小型硬板加绑带；用户确认后继续。
3. **授权 AI 持续完成**：用户可让它继续执行，在需要取舍时由用户决策，或启用“替我完成”。

### AI 代理执行的子任务

- **查资料与选型**：搜索符号/器件、查询验证库、读取数据手册或商品资料页。
- **核对器件工程信息**：读取引脚、搜索封装、检查引脚兼容性。
- **构建电路**：添加/删除器件、连接网络、生成原理图。
- **处理结构与制造约束**：询问供电方案、设置板框尺寸和层数。
- **校验并汇报进度**：运行检查、显示成功/失败/待处理项，汇总 DRC 与未布线状态。
- **读取与解释现有设计**：`Load design` 后说明传感器已存在，缺少的是数据/中断连接，并列出后续工作。
- **暂停与续接**：`Paused with work left` 保留未完成项，通过 `Continue the build` 或输入 continue 接着做；也可 `Request changes`。
- **无变更结果反馈**：本轮只是读取设计时明确说明没有板卡变更，并收集用户对结果的反馈。

## 产品框架结构（根据截图归纳）

```text
项目 / 设计文件
├── 对话代理 Inky
│   ├── 需求理解与约束冲突识别
│   ├── 方案澄清与用户决策
│   ├── 工具任务流：查器件 → 查规格/引脚/封装 → 增删元件 → 连线 → 生成/校验
│   └── 进度、失败状态、决策记录、阶段总结、暂停/恢复
├── 设计工作区
│   ├── Schematic：原理图
│   ├── PCB：板框、层、布局、布线与 DRC
│   ├── 3D：板卡空间呈现（顶栏入口）
│   └── Mech：机械结构（顶栏入口，截图标为付费功能）
└── 项目操作
    ├── 版本历史 / 撤销重做
    ├── 下载 / 分享
    └── 库与人工编辑工具
```

关键框架不是简单的“聊天窗 + 预览窗”，而是**AI 代理与可编辑工程文件共享同一工作区**：AI 的步骤直接改变右侧设计，用户也能随时切换不同设计视图或手工操作。工具任务作为可展开记录出现在对话里，用户可以看它查了什么、哪一步失败、目前还差什么。

## 对 BMC / openUBMC Studio 的借鉴

### 优先借鉴

1. **把对话绑定到当前工程对象。**在 CSR 或拓扑编辑器里，用户说“检查 IEU 的管理路径”，AI 应能使用当前板卡、拓扑和选中节点上下文，并把结果落到实际图或配置中。
2. **把隐含约束转成明确澄清。**类似 FR-4 与弯折需求冲突，BMC 工具应在用户要求与数据/协议约束不一致时说明冲突、给可选方案，并等待确认；例如区分物理连接、I²C sideband 和软件映射。
3. **显示代理做事的步骤和状态。**把“查询 CSR → 定位节点 → 检查 refConnector → 对比约束 → 提议修改”分步呈现，支持展开依据、失败原因和结果定位，避免只给一段无法追溯的答案。
4. **让每次自动修改可见、可撤销。**展示改动前后字段、节点与连线差异；对拓扑结构、传感器绑定等操作提供应用/撤销入口和版本历史。
5. **让检查状态与工程产物一致。**早期空设计显示“DRC clean”，后续设计出现 19 个错误；两者属于不同阶段，仅据截图不能判定校验器存在错误。借鉴时应标明检查对象、版本、覆盖范围和当前结论，区分“局部无错误”“完整检查通过”“仍有未处理项”。
6. **把专业视图作为最终落点。**对话负责搜寻、解释、提出变更；拓扑画布、CSR 表单和配置视图负责确认实际结构，用户不必把聊天里的建议手动搬回工程。

### 适合落地的 BMC 场景

- 用自然语言定位板卡、芯片、I²C 总线或 Scanner。
- 解释某个传感器的读取路径与软件引用关系，并在图上高亮路径。
- 批量生成/修改传感器、事件或组件配置前，先展示变更预览。
- 基于已知约束进行一致性检查，例如 `refConnector` 是否有效、IEU I²C 是否走 Hisport sideband。
- 将检查结果关联到具体节点与字段，支持逐项修复和重新验证。

### 不宜照搬

- PCB 设计可以容许较长的后台代理任务；CSR 日常编辑往往需要快速、精确、可审查，不能因自然语言而弱化字段级控制。
- 不要把“AI 已修改”包装成“工程正确”。协议、硬件关系和固件行为需要确定性检查；AI 可提出方案，校验器和工程师确认结果。
- “替我决定”只适合可逆、低风险的偏好。涉及硬件事实、配置覆盖或可能影响出包的更改，应默认先询问并展示影响范围。
