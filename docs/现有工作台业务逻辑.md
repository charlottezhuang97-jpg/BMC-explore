# 现有工作台业务逻辑梳理

## 工程加载

1. 选择整机项目。
2. 如果有 `rootSrPath`，读取样例 SR。
3. 解析并写入 CSR 状态。
4. 设置当前工程和文件名。
5. 打开拓扑视图。

没有当前 CSR 时，部分 CSR 依赖视图会尝试加载默认样例；这适合 Demo，但正式产品需要清楚区分“真实工程”和“示例工程”。

## 编辑与保存

- 拓扑、事件、传感器等视图通过 `onChange` 更新 CSR。
- 更新后设置 dirty 状态。
- 在 VS Code 环境中发送 `saveContent`；在浏览器中下载 `.sr` 文件。
- CSR 编辑类视图的保存按钮按 Tab 上下文显示。

## Agent 任务

- 通过关键词按数组顺序匹配第一个任务。
- 回放工具轨迹和模拟输出。
- 任务结束后可打开关联视图。
- 安装任务可以回写向导检测状态。

## 已确认的业务风险

- 关键词首个匹配会影响任务选择，命令存在歧义时用户不一定知道匹配结果。
- 模拟任务输出与真实执行结果需要在 UI 上明确区分。
- 任务结束打开视图不等于用户知道修改内容，需补充变更摘要和验证结果。
- 保存/出包是高影响动作，应显示工程、文件、校验、签名和输出路径。
